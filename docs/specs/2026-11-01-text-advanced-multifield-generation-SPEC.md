## 0. 决策摘要与范围

目标是**完整保留现有 Text Easy 行为**，在同一 Text 标签中新增 Advanced。Advanced 在一次生成操作中，读取一条 Anki 笔记**已经存在**的 1 至 N 个文本字段，通过提示词对不同输入字段分别引用，生成 1 至 M 个目标字段；目标字段与全部源字段互斥。Advanced **不允许 OCR、视觉模型请求、音频/视频解析或中间结果自动生成**。当前 Easy 的单源单目标以及现有 Image Recognition 不迁移到 Advanced。

两种模式共用 Prompt Preview、Prompt Name、Search、New、Save、Save As、Delete、Import、Export 控件和模型配置，但 Prompt 列表、内置 Default、最近使用状态和执行协议隔离。保留左侧 Import/Export 和右侧四个 Prompt 操作按钮布局。字段选择仍位于 Text 页面底部同一行，不引入第二套生成页面。

高级模式**输入占位符**使用真实字段名 `{Text}`、`{Scenario}`；**输出声明**使用 `{OUT:Translation}`、`{OUT:Note}`。生成前强制校验“勾选集合 = 提示词声明集合”（输入和输出分别独立校验）。验证失败弹出明确错误并在**任何 LLM 请求和任何笔记写入之前拒绝整个生成操作**。多输出由程序要求并解析可验证的结构化响应，再以每笔记一次写入提交。

不包含：将不同笔记中的字段跨笔记关联、链式依赖生成、多轮自动循环、添加/删除 Anki 字段、为不同 Note Type 自动改名映射、让输出字段成为同次生成的输入、Prompt 共享网络服务、重写 Audio。

## 1. 现有代码事实与兼容性基线

以下为本 SPEC 编写时对冻结 Commit 的静态核对；**不是已通过运行测试的结论**。

1. `ainotepro/ui/text_tab.py` 的 `_load_note_fields()` 从所选第一条笔记的 Note Type 取得字段名，`source_field_combo` / `destination_field_combo` 均为单选 `QComboBox`。
2. `on_generate_text()` 有两条路径：Image Recognition 的单条视觉路径，以及纯文本批量路径。后者把 `(nid, source_text)` 交给 `GenerationWorker`；线程中使用 `prompt_tpl.replace("{Source Field}", text).replace("{Source}", text)`，仅返回单字段普通文本。
3. `_apply_generated_text_result()` 和视觉路径通过 `ainotepro/core/utils.py::update_field_content()` 写入，该函数设置一个字段并立即 `note.col.update_note(note)`；**不能直接在多输出循环中调用以实现一次性写入**。
4. 当前 `_confirm_write_risk()` 在同源同目标或批量笔记时提示；`create_undo_checkpoint()` 是 best-effort 尝试，失败只打印日志。Advanced 需要单独验证实际 Anki 的撤销与提交边界。
5. Easy Prompt 使用 `text.prompts` 平面字典与 `text.last_used_prompt`；`_load_prompts()` 合并内置 Default、遗留 `user_files/gen_text/prompt.json` 镜像和用户配置，`_save_prompts()` 写配置并尝试写镜像。当前 Default 已受保护且可编辑后 Save As。
6. `ConfigManager.update_text_fields()` 当前白名单仅包含 `prompts` 和 `last_used_prompt`；`_replace_raw()` 有原子文件替换和跨域保护，但无专用 Text 域 CAS；`save_all()` 等旧入口的影响需要逐一核对。
7. 文本/音频设置与模型 Provider/Reasoning 保存存在于同一用户配置，新增 Advanced 存储不得重置这些配置。

审计人必须对照冻结代码逐项核实；如现状不符，记录事实差异和阻断项，不得以本 SPEC 代替源码事实。

## 2. UI 与模式状态契约

### 2.1 Easy（零行为回归）

Easy 为打开旧安装和迁移后的默认 Text 模式。Source 单选、Destination 单选、`{Source Field}` / `{Source}` 原有替换语义、Image Recognition、原有 Prompt 名称/内容、Provider 配置、现有生成行为、写入警告和回退体验必须维持。不得强制旧 Easy Prompt 使用 Advanced 占位符或 JSON 输出。对 Easy 的安全修复若不可避免，需单独说明和验证，不得借本任务默改其语义。

### 2.2 Advanced 字段行

在现有底部 Field Mapping 行放置 Easy/Advanced 切换，尽量保持单行高度与现有 Source/Destination/Image Recognition 的紧凑布局。Advanced 的 Source 和 Destination 都通过带勾选项的弹出列表进行多选；列表收起后用可读文本展示选中字段名（多项可省略并通过 tooltip 展示全量）。不得把列表变为常驻多行控件。

- Source 选中数量至少 1；Destination 选中数量至少 1；不设置人为 1:1 限制。
- 同一真实字段不得同时出现在源、目标；UI 中冲突项应禁选或者选择时明确处理冲突，**不得静默替用户改变另一侧选中集合**。建议禁选并标注原因。
- 字段列表只来自当前 Note Type 的**真实字段名**；保留其顺序及大小写。选择集不重复。
- Advanced 禁用/隐藏 Image Recognition，任何隐藏状态也不得影响后端：Generate 强制使用纯文本请求路径；切回 Easy 恢复原先 Image Recognition 的选择状态。
- Easy/Advanced 分别维护本会话中的 Source/Destination 选择；切换模式不应丢失另一模式已选值、无提示覆盖尚未保存 Prompt，也不能自动启动生成。
- 字段勾选变更不能私自修改**已保存自定义** Prompt 文本；不符合选择规则时由生成前校验拒绝。
- UI 须为“无选中笔记”“字段缺失”“多 Note Type 混选”“不支持的媒体输入”提供可理解的错误提示；不得以默认选择第一项掩盖不存在的字段。

### 2.3 Note Type 范围

Anki 的字段属于 Note Type，而不是 Deck。V1 一次批量运行必须选取具有**同一 Note Type 标识和兼容字段定义**的笔记；若混选不同 Note Type，在发出网络请求前**整批拒绝**并报告，不按字段名碰巧相同就混合处理。更换所选笔记时应刷新可选字段，已不存在的字段选择视为失效并阻止 Generate，而非自动重映射。

## 3. Prompt 命名空间、Default 与配置迁移

### 3.1 共用 UI，独立数据

Easy 和 Advanced 共用唯一的 Prompt 编辑器与管理按钮，但 Prompt 列表只显示当前模式的条目。名称在各自模式内唯一（大小写折叠冲突拒绝）；两模式可存在同名自定义 Prompt。

**固定存储合同：** 完整保留 `text.prompts` 和 `text.last_used_prompt` 作为 Easy 既有存储；独立增加 `text.advanced_prompts`（平面名称→正文）、`text.advanced_last_used_prompt`、`text.field_mode`。不得将原 `text.prompts` 原地改为嵌套字典。模式域 CAS 的权威数据、规范化和初始化规则以 §12.1 为准。

- 旧 Easy Prompt、包括历史自定义 Default 内容、顺序、最近使用名称及 `prompt.json` 镜像不丢失、不被 Advanced 模式读取成执行模板。
- Advanced 自定义 Prompt 不写进 Easy `prompt.json` 镜像；高级模式 Import/Export 要采用显式模式作用域和向后兼容格式，必须防止将 Advanced 文件误导入 Easy。
- 修改 `ConfigManager.update_text_fields()` 白名单及必要的加载/保存入口，严格限定只写对应 Text 域字段；不得覆盖其他窗口的 Audio、更不能丢失 Provider API Key 或其他未知配置键。
- 对并发窗口保存同一 Prompt 列表必须提供冲突检测或等效合并保护；不能只因为整文件写入原子就认为不会发生丢失更新。保存失败保留用户草稿，告知错误。
- 明确兼容老用户配置、旧版升级、损坏文件、重复打开、导入/导出、删除、回滚后的安全行为；未知未来字段必须保留。

### 3.2 Advanced Default 是动态示例

Easy Default 保留原有内容与保护规则，**不重置用户曾经自定义的 Easy Default**。

Advanced 有独立的、不可删除和不可直接覆盖的**虚拟 Default**，**不要求在磁盘上按每种字段组合存储**。打开或选择 Advanced Default 时，基于当前 Note Type 和 Source/Destination 勾选自动生成带真实字段占位符的示例：

~~~text
已有输入：
Text: {Text}
Scenario: {Scenario}

生成以下目标：
{OUT:Translation}
请给出自然中文翻译。

{OUT:Note}
简要说明语言学习要点。
~~~

示例只是示意；实际文案必须由**当前勾选集合**动态生成，且每个被勾选字段恰好声明一次。用户可以在预览中临时编辑后 Save As 为自定义 Prompt；不允许把当前草稿保存回虚拟 Default。

当 Default 预览已有用户未保存编辑而字段集合变化、模式变化、切换 Prompt 或 Note Type 时，必须通过确认保留草稿、丢弃或取消切换（例如 Save As / Discard / Cancel，或等效流程），不得不经提示重生成覆盖草稿。自定义 Prompt 不随着字段选择改变而被改写；只在 Generate 时进行严格一致性校验。New、Save、Save As、Delete 的现有易用语义保持，并在 Advanced 名称空间内操作。

## 4. Advanced 提示词语法与严格校验

### 4.1 占位符语义

- **输入引用：** `{字段名}`，例如 `{Text}`、`{中文说明}`、`{Example Sentence}`。引用字段名与 Anki 实际字段名严格匹配；不区分真实字段名的假设禁止。
- **输出声明：** `{OUT:字段名}`，例如 `{OUT:Translation}`。这不是用户输入的替换值，而是明确告诉执行器要生成哪个目标字段。
- Advanced **禁止**把所有源字段合并后放进 `{Source Field}`；`{Source Field}` / `{Source}` 只属于 Easy。Advanced 应把每个独立输入占位符替换成对应源字段的内容。
- 必须以词法解析/一次映射替换实现，不得依次使用 `str.replace()` 造成新插入文本中的 `{...}` 二次展开。解析在插入笔记内容前完成；用户的字段文本是数据，不能触发占位符解析。
- 允许同一输入字段**重复引用**，但源字段集合按唯一名称计算。目标字段必须恰好**声明一次**：重复 `{OUT:X}` 拒绝。
- 字段名解析及保留前缀的完整、无歧义词法规则以 **§11.1** 为准。中文、空格、普通冒号可用；包含大括号、保留前缀等边界严格按 §11.1 处理。
- 普通 JSON 示例、代码块和其他字面大括号必须用 **§11.1** 的固定转义；未转义的不合法单花括号须拒绝生成，不猜测其意图。

### 4.2 生成前集合相等校验（用户确定的硬要求）

记 `S` 为 UI 勾选的真实 Source 字段集合，`D` 为勾选的真实 Destination 字段集合；`IS` 为提示词解析所得**唯一输入引用集合**，`OD` 为提示词解析所得**输出声明集合**。在每次点击 Generate 时，必须全部成立：

1. `|S| >= 1`、`|D| >= 1`、`S ∩ D = ∅`。
2. `IS = S`，即已勾选输入一个也不能缺，未勾选输入一个也不能多；分别显示缺失与多余名称。
3. `OD = D`，已勾选输出一个也不能缺，未勾选输出一个也不能多；输出声明不得重复。
4. 不接受未知字段、非法/有歧义的引用语法、Easy 专用占位符或输入输出角色混淆。
5. 当前笔记选择和 Note Type 全部有效，全部选中笔记都有 `S ∪ D` 字段；Prompt 不为空；Provider/模型配置满足原有生成前检查。
6. **检查在任何发送请求、创建写入检查点和修改笔记前完成**。任一失败以清楚列出字段名、缺失/多余类别的警告**拒绝整批生成**，不得降级为 Easy 或偷偷缩减字段集合。
7. Save/Save As 可以保存未匹配当前字段组合的自定义 Prompt 草稿；一致性是**Generate 前检查**，避免用户编辑中被强制改写。

Example：Source 勾选 `Text, Scenario` 而 Prompt 只出现 `{Text}`，报缺少 `{Scenario}`；Destination 勾选 `Translation, Note` 而仅有 `{OUT:Translation}`，报缺少 `{OUT:Note}`；Prompt 引用未勾选的 `{Extra}` 同样报错并拒绝。

## 5. 输入来源边界（Advanced 不支持 OCR）

Advanced **只读取每条笔记在运行开始时已持久存在的字段文本**；绝不在本次执行中创建 OCR、图片描述、语音识别等中间内容。用户如需处理 PPT 截图，先通过 Easy 的 Image Recognition 将识别结果写入独立字段，检查后再执行 Advanced。

- 源字段可含普通 Anki HTML 富文本；需要有确定的 HTML→可读文本转换规则，保留必要换行/标点，处理 HTML entity，并防止图片 `<img>`、音频 `[sound:...]` 等媒体标签被错误当作图像/语音内容；不能下载 URL、读本地媒体文件或提交多模态载荷。
- 只要**任一**选中笔记的**任一**勾选 Source 字段在 §11.8 规定的纯文本转换后为空（包括仅有图片、音频、空白），必须在**全批预检**阶段拒绝整批：零模型请求、零笔记写入；不能部分继续。
- 批量任务在 Anki 主线程/受支持的 collection 线程先获取每条笔记必要的纯文本及目标字段值、Note Type、版本/变更证据；工作线程只能使用这个不可变快照。后续输出不回流为本轮其他输入，不跨笔记引用。
- 生成过程应设上限和报错策略（单字段内容过大、批量过大、模型上下文不足）；不得在未经用户确认时静默截断文本。避免在日志中输出完整字段内容或 API Key。
- 包含敏感笔记信息的多字段输入仅发送至界面已选择的 Provider；不得自动发送到其他服务。

## 6. 输出协议、解析和写入事务

### 6.1 插件管理的输出协议

用户在 Prompt 中负责描述 `{OUT:字段名}` 应生成的**内容要求**，**不需要手写 JSON**。输出指令分段与编译遵守 §11.3：第一个输出声明前是全局指令，每个输出声明到下一声明或结束是该输出字段的指令段。插件根据 `D` 自动附加确定、可测试的输出协议，要求模型返回**单个 JSON 对象**，键为真实目标字段名，值为字符串。例如：

~~~json
{
  "Translation": "可能很难融入进去。",
  "Note": "It might be hard to... 可用于表达预期困难。"
}
~~~

Advanced 无论目标 1 个还是多个，都使用**同一 JSON 协议**，避免单输出纯文本/多输出 JSON 两套行为。单条笔记一次 LLM 请求，不允许自动进行隐式第二轮 LLM 补全、OCR 或依赖链生成。可以添加原生结构化输出参数作为可选能力，但不得假定所有 OpenAI-compatible、Ollama、本地端点都支持同一参数；默认有可跨 Provider 使用的文本输出校验路径。

`{OUT:...}` 是受解析器识别的输出声明，必须编译成 §11.3 的字段指令段和统一 JSON 契约，不得将原始标记直接发送给模型。

### 6.2 收到响应后的硬校验

任何字段写入前必须按 **§11.3** 的严格规则解析响应：仅单个完整 JSON 对象或完整包裹该对象的一层 `json` code fence；不得截取自由文本；无重复键、无未知键，键集合**恰好等于** `D`，每个值必须是非空字符串；不得将错误文本、拒绝消息或模型未生成结果写入笔记。不能用宽松的正则截取结果或依赖字典遍历顺序分配字段。响应不合格时该笔记所有目标字段**零写入**，显示失败原因，不得部分提交。

### 6.3 目标覆盖与原子性

- 所有目标字段均是用户已明确勾选的已有 Anki 字段。**禁止自动新建字段**，禁止写入输入字段。
- 目标字段已有内容的处理规则必须明确、保守、可见：V1 在生成前对“将覆盖非空目标”的笔记与字段进行批量汇总预览，并要求用户明确确认；用户取消则整批不执行。不得静默追加，也不得因为多个目标同时选择就覆盖未勾选字段。
- 每条笔记完成全部输出校验后，在 Anki 许可的 collection/UI 线程上重新读取该笔记，校验 Note Type 和所有相关 Source/Target 是否与运行快照一致；若被其他操作修改，**该笔记零写入**并报告冲突，不覆盖并发编辑。
- 在**单个 note 对象**上设置全部目标字段，调用**一次** `update_note`（或等效的 Anki 官方原子/撤销 API）；不得复用当前每字段一次提交的 `update_field_content()` 循环。若底层提交失败，不能报告成功；需通过 Anki 支持的事务机制保证该笔记不存在半更新。每笔记原子，不要求跨整批所有笔记进行全局事务。
- Advanced 的 Anki Undo 与提交/成功反馈顺序按 **§11.5** 验收；必须实测真实 Anki 环境，不得把目前 best-effort `create_undo_checkpoint()` 作为事务保证。批次已成功的其他笔记不因某一条失败而被静默回滚。
- 不允许 worker 线程直接读写 `mw.col` 或修改 Qt 控件；UI 关闭/取消后不得再写入已经失效的结果。进度、失败、取消、恢复与重复点击 Generate 要有确定状态机。

## 7. 实施范围与建议模块

1. **Text UI：** `ainotepro/ui/text_tab.py` 增加模式切换、多选下拉、互斥禁选、模式独立状态、Advanced Prompt 展示与 Generate 分流；不得将复杂校验全部堆入 Qt 回调。
2. **独立纯逻辑模块（建议新增）：** `ainotepro/core/advanced_text.py`，负责实际字段名解析、字段集合校验、Prompt 编译/单次替换、HTML 纯文本输入、结构化输出解析与验证。要求无 Anki/Qt 依赖，能单测。
3. **生成编排：** 复用纯文本 Provider/worker 概念但为 Advanced 定义明确的快照/请求/结果数据结构；Easy 的 GenerationWorker 与视觉生成路径可以不动。避免跨线程访问 note 对象。

### 11.1 AUD-AT01 — 占位符词法、转义和字段名边界（BLOCKER）

Advanced Prompt 使用**单遍从左到右扫描**，在插入任何字段内容前完成词法解析和语义校验。解析结果为带源位置的 AST / token 序列，而非对整段文本连续调用 `str.replace`。明确语法：

- `{{` 表示**字面** `{`，`}}` 表示**字面** `}`；只允许这两个双字符转义。普通 JSON、代码样例、正则含大括号的部分都必须用此规则转义。例如 `{{"key":"value"}}` 渲染为 `{"key":"value"}`，不产生字段 token。
- 未转义的单 `{` 开始 token，必须以其后的**第一个**单 `}` 闭合，token 内禁止任何 `{` 或 `}`；未闭合、孤立单 `}`、空 token `{}`、包含换行的 token、嵌套/三重花括号均报语法错误。扫描器须优先识别双括号转义，不能先执行字符串全局替换。
- token 内字符不做空白裁剪、不做大小写归一化、不做 HTML 反转义；`{Example Sentence}`、`{中文释义}`、`{A:B}` 可直接按实际字段名精确匹配。**真实 Anki 字段名本身包含 `{` 或 `}` 时，V1 拒绝把该字段选入 S 或 D**，错误信息列出字段名，不误映射。
- 若 token 内容以精确大写 `OUT:` 开头，则一定是输出声明：去掉一次前缀，其余字符串必须与 D 中某个完整字段名**精确一致**。例：`{OUT:Note}` 输出 Note；实际输出字段名为 `OUT:Note` 则写 `{OUT:OUT:Note}`。不是已选输出的声明应作为“额外/未知目标”报错；不得退化为源引用。
- 否则 token 一定是输入引用，内容必须与 S 中真实字段名精确一致。为消除角色歧义，**源字段名以 `OUT:` 开头、或恰好为 `Source Field` / `Source` 时，在 Advanced V1 不支持**，预检明确拒绝；目标名无此保留前缀限制（大括号限制仍生效）。
- `{Source Field}`、`{Source}` 在 Advanced 属 Easy 专用非法 token，即使 S 中未选同名字段也必须明确报错。
- 不认识的单花括号 token 不能视为可忽略文字；必须报“未知/未勾选占位符”并拒绝。要显示字面 `{Unknown}`，必须使用 `{{Unknown}}`。源码插入的笔记字段文本**不再扫描**，其中出现任何 `{...}` 均按普通用户数据保留。
- 源 token 可重复，按去重后的 IS 比较；**输出 token 不得重复**。词法错误优先于集合差异，在统一预检错误对话框中展示 token 位置与原因。输出声明不得出现在双括号字面文本中。

正例：`Use {Text} and {Scenario}. {OUT:Translation} Translate them.`（S 为 Text、Scenario，D 为 Translation）；`Schema: {{"name":"example"}}` 是字面 JSON。反例：`{OUT:Translation`、`{Text{X}}`、`{"a":1}`（未转义 JSON）、`{OUT:Translation}` 重复两次、S 含 `OUT:Note`、S 含大括号。字段名中英文大小写或前后空格不同，都不允许自动纠正。

### 11.2 AUD-AT02 — 全批预检与空源策略（BLOCKER）

Generate 点击后先完成**同步于任何副作用之前**的纯逻辑与数据预检：验证笔记选择、Note Type 唯一性及字段定义、S/D 非空和互斥、Prompt 语法及 IS=S / OD=D、字段在每条笔记均存在、每一个选中 Source 的 §11.8 纯文本结果非空、文本大小约束、媒体-only 来源；然后汇总全部失败并**拒绝整个批次**。任何一条笔记、任一源字段不满足条件都整批失败，**零 Provider/模型网络请求、零保存模型设置、零 Undo 检查点、零笔记写入**。参数验证若需要网络探测须在纯预检通过之后且写入之前进行；网络探测失败不得写入。

输入字段存在但转为纯文本后为空，**不能以可选字段或空字符串继续生成**。目标字段已有非空值不属于预检失败，但需执行 §11.5 的覆盖确认；取消确认视为整批零写入。批次开始后出现的网络失败或并发冲突按每笔记失败处理，不重新回滚已成功笔记。

### 11.3 AUD-AT03 — 输出分段、编译及严格 JSON（BLOCKER）

在通过词法解析后的 Prompt AST 上，以**第一个** `{OUT:X}` 为分界：其前全部文字（包括输入引用）为**全局指令段**；每个输出声明之后直到下一个输出声明或正文结束的文字为对应目标的**专属指令段**。每个 D 项恰好出现一个声明。允许任意非空自然语言要求（全局或专属）；专属指令段不得仅空白，空白段拒绝生成。专属段可以引用任意已选 S 的输入 token；不允许嵌套输出声明。**输出目标的顺序即声明出现顺序**，不影响结果按键名映射。

编译后的请求由：渲染后的全局指令、按声明顺序列出的「目标字段真实名称 + 对应渲染后的专属指令」、以及插件附加的固定结果协议构成；不将原始 `{OUT:X}` 标记直接发送给 LLM。源字段插入时对文本执行单次替换，不解析其内部花括号。所有目标说明归属固定由边界决定，不能使用模型或启发式猜测。

统一要求模型只返回 **UTF-8 JSON 对象**，顶层键为 D 中真实字段名，值是非空字符串；不允许顶层数组、嵌套对象或非字符串值。解析器允许两种且仅两种完整响应：**(A)** 前后只有 JSON 合法空白的单个对象；**(B)** 完整外层围栏 ```json + 换行 + JSON 对象 + 换行 + ```，围栏外只允许空白；`json` 标签大小写严格为小写。不得从额外说明、多个对象、未闭合围栏中截取片段或尝试自动修复、发起第二轮生成。使用有重复键检测的 JSON 解码（如 `object_pairs_hook`）；未知键、重复键、缺失键、键名大小写变化、空/纯空白字符串均使**该笔记所有目标零写入**。响应在解析前应有有界大小限制，超限拒绝，不回退为纯文本。默认不依赖特定 Provider 的 JSON Schema 参数。

示例输出（D=Translation、Note）：`{"Translation":"可能很难融入进去。","Note":"这句话表达预期的困难。"}`。反例：`Here is JSON: {...}`、`{"Note":"a","Note":"b"}`、`{"Translation":"ok"}`、`{"Translation":null,"Note":"ok"}`，一律失败。

### 11.4 AUD-AT04 — Prompt 保存的并发 CAS 与删除（MAJOR）

Easy 持久数据仍保留为 `text.prompts` / `text.last_used_prompt`；Advanced 新增独立 `text.advanced_prompts` / `text.advanced_last_used_prompt`。Prompt 修改使用**模式域 CAS**：窗口载入时保存该模式 Prompt 字典的规范序列化摘要；Save/Save As/Delete/Import 时在现有 `_CONFIG_LOCK` 内重新读取磁盘同模式字典并核对摘要；不一致则拒绝并保持当前草稿，提示重新加载或人工解决冲突，**不得静默覆盖**。成功后返回并更新已提交的摘要。Easy 和 Advanced 之间不产生虚假的 Prompt 编辑冲突；Provider/Text 其他键和 Audio 的并发变化亦不能被旧快照覆盖。空配置初始化的期望摘要与缺键状态均必须遵守 §12.1 的**单一规范化定义**，不能计算 UI 合并结果的摘要。

`user_config.json` 的 Prompt 字典为长期**唯一权威来源**。旧 `prompt.json` 只能在**一次受控、幂等的迁移**中合并：保留旧有效 Prompt，冲突时以用户配置中的同名内容优先，迁移成功后记录完成标志；之后只允许作为**向外写的兼容镜像**，任何正常加载都不再从镜像补回被删除条目。删除事务先原子提交配置中的删除及元信息，再尝试刷新镜像；镜像写失败要告警并允许重试，但不得将镜像中的旧数据重新导入。不能把“配置缺失”自动当成“重新运行历史导入”，须保留迁移标识/删除语义。历史 customized Default 原文不得重置；Advanced 虚拟 Default 不写入自定义 Prompt 字典。

Import/Export 在对应模式内显式标识目标模式，旧版不带模式的 JSON 按 Easy 处理；Advanced 不自动把旧版文件识别成 Advanced。跨模式误导入、同名覆盖和 CAS 冲突必须有确定的拒绝/确认逻辑；任何未知配置键保留。

### 11.5 AUD-AT05 — Anki 单笔记提交、Undo、提示顺序（MAJOR）

每条有效模型响应先通过 §11.3 验证，再在 Anki 允许的 collection/UI 线程按 §11.6 复核源/目标快照；**一次性给同一个 note 对象设置全部目标字段，且每条笔记仅调用一次支持撤销的提交操作**。所有目标必须同进同退；不得先写成功一个字段再写下一个，不得在中途调用现有逐字段 `update_field_content()`。

在部署目标 Anki 版本上必须通过真实数据库/官方 Undo API 验证：该笔记提交成功后执行 Undo，**所有**本次目标字段恢复到提交前原始存储值，未选字段不受影响。checkpoint 失败、Undo 不可用或数据库部分失败时，不得报告成功；如果不能保证此合同，Advanced Generate 必须被禁用或阻断发布，**不得以 best-effort checkpoint 静默继续**。禁止声称简单一次 `update_note()` 已自动满足撤销合同。

**顺序：** 完成数据与并发校验 → 获得经验证的 Undo/事务上下文 → 一次提交 → 确认提交结果并使 Undo 可用 → 同步刷新编辑器/UI → 发出用户成功计数或提示。失败的笔记不能计入成功，UI 刷新失败必须反馈“不确定/需刷新”，不得谎称全部完成。批量操作采用逐笔记独立提交；已成功的其他笔记保留，可通过 Anki Undo 恢复，并需在实机记录 Undo 历史的实际合并/分组行为。

### 11.6 AUD-AT06 — 快照及冲突比较（MAJOR）

每笔记预检完成后保存不可变快照：Note ID、**Note Type ID、字段名及顺序的完整定义**、S 与 D 的全部**原始存储字符串**（HTML/实体编码未经转换），加上纯文本输入的派生结果。实际模型输入仅用已转换的纯文本；快照比较必须用原始值。

在提交前重新读取同一 Note ID，比较 Note Type ID、完整字段名顺序以及所有 S/D 原始值；**任何一项不同都视为并发冲突，此笔记全部 D 零写入**。最后一次检查至写入提交必须构成 §12.2 规定的**不可让出执行权的操作单元**。修改时间可以记录诊断但**不能单独作为判断依据**；即使修改时间相同也必须检查值。只需比较涉及字段，其他非 S/D 字段外部变化不得被插件覆盖；提交时使用重新读取的 note 对象设置目标字段而非使用陈旧 note 对象。

### 11.7 AUD-AT07 — 取消与关闭状态机（MAJOR）

V1 每个 Text 窗口最多一个 Advanced 任务；状态：`IDLE → PREFLIGHT → RUNNING → (CANCELLING) → FINISHED/FAILED → IDLE`。PREFLIGHT/ RUNNING/CANCELLING 期间禁用重复 Generate；不得启动重叠任务。

- **Cancel**：原子设置取消标志；不启动新 LLM 请求；正在执行的请求可完成或超时，但结果**一律丢弃，不得再提交**。此前已经完整提交并报告成功的笔记保留。必须在准备提交前**再次检查取消标志**；已进入不可中断数据库提交的笔记完成当前提交后才视为成功，不允许半提交。完成后通知本批成功/失败/取消计数。
- **窗口 Close/Esc/标题栏关闭**：若有任务，先发起与 Cancel 相同的取消，阻止新请求和后续写入；后台任务可在安全状态终止后释放资源，不能在控件已销毁后再触发 Qt 回调或 Anki 写入；不得在 UI 线程做阻塞等待。
- **异常**：Provider 超时、解析失败或单笔记冲突使该笔记失败，不能把错误文本写入；在未取消且安全情况下可继续下一条。任务生命周期绑定有效 UI/collection 会话，后台不得持有可直接调用已销毁控件的回调。对话框关闭后完成的请求不再计入新批次。

### 11.8 AUD-AT08 — HTML→文本确定规则（MAJOR）

采用单一、可单测的 HTML-to-text 转换，输入是存储的字段 HTML 字符串：按 HTML 元素树顺序提取可见文字；`<br>` 转换为 `\n`，`<div>`、`<p>`、列表项等块元素边界最多一个 `\n`；HTML entity 解码一次；删除标签但保留其普通可见文本；Cloze **现存字段原始 `{{cN::答案::提示}}` 语法须提取答案文本**（没有提示时同样），不得把 `cN::` 控制内容发送给 LLM。删除 `<img>`、`<audio>`、`<video>`、`<source>` 等媒体节点与内容，移除所有 `[sound:...]`，不读取文件、不请求 URL；`<script>`、`<style>` 的内容全部丢弃。移除不可见标记中不属于可读文本的控制信息。统一 CRLF/CR 为 LF，折叠连续空白行到最多一个空白行，非换行连续空格折叠为一个，最后 trim。

**“非空文本”**定义为按上述规则转换后仍至少包含一个非空白 Unicode 字符；不要求是英文。只有媒体、空 HTML、只有换行或空格、只有脚本样式而无可见文本，都视为无效源。单个 S 为空即全批拒绝，见 §11.2。字段中的图片 alt、媒体路径和 URL 属性不算 OCR 结果，不作为输入；普通正文中的 URL 字面文本可以保留。

固定验收样例：
| 原始字段 | 结果 |
|---|---|
| `A<br>B` | `A\nB` |
| `<div>Hello</div><div>world</div>` | `Hello\nworld` |
| `&amp; &lt; &gt;` | `& < >` |
| `{{c1::answer::hint}}` | `answer` |
| `<img src="slide.png">[sound:a.mp3]` | 空（整批拒绝） |
| `<p>Hi <b>there</b>.</p>` | `Hi there.` |
| `<script>secret</script><p>Good</p>` | `Good` |

测试需覆盖深层嵌套、实体二次编码、HTML 损坏、Unicode、Cloze 多编号、媒体 alt、脚本样式及过长文本。Cloze 嵌套和异常格式必须依据 §12.3 解析，不允许把残留控制语法传给模型；转换库不得在后台读取 Anki collection。

### 11.9 AUD-AT09 — 动态 Default 草稿状态（MINOR）

Advanced Default 状态严格为：
- `generated`：由当前 Note Type、S、D 自动产生，未编辑；选择变化可无提示重新生成；不写持久配置。
- `edited-unsaved`：用户修改动态 Default 的正文；任何可能触发重新生成的字段变更、Note Type 变化、模式/Prompt 切换、关闭窗口，都必须先提出 **Save As / Discard / Cancel**；Save As 成功转为 `saved-custom` 并继续原操作，失败或 Cancel 则撤销原操作并保持完整草稿；Discard 丢弃并按新选择重新生成。禁止自动 Save 覆盖 Default。
- `saved-custom`：已用 Save As 命名保存的静态 Advanced Prompt；今后字段勾选变化不自动修改其正文；切换前有未保存编辑应走既定 Save/Discard/Cancel 防护。

New 创建独立未保存自定义草稿，Save 才创建正式条目，Save As 另存新名；同样不允许因为模式切换而静默丢草稿。Easy Default、Easy 自定义 Prompt 仍维持旧模式保护语义。

### 11.10 AUD-AT10 — Qt 跨平台 UI 门槛（MINOR）

必须分别在 macOS、Windows、Linux 的受支持 Anki/Qt 实际运行环境检查至少 **1000×700 与 870×610** 两种窗口尺寸：模式开关、Source/Destination 标签与可点击多选入口、Easy Image Recognition、底部 Generate/Close、Prompt New/Save/Save As/Delete 均可见且可操作，不得水平截断或相互覆盖；若控件总宽不够，应缩短摘要、提供 tooltip 或经过验证的自适应布局，不能依赖更改用户窗口大小才可使用。弹出多选列表可滚动、有键盘焦点和方向键/空格勾选操作、Escape 关闭不丢已确认选择；所有已选字段名可通过 tooltip/辅助文本完整读取，禁选冲突项应可识别。不同 DPI/缩放、中文长字段名、多选 10+ 字段需人工验收。不能只用“Qt 支持跨平台”代替证据。

## 12. 第二轮 CONDITIONAL PASS 定向整改合同（R2）

本节只针对 AUD-R2-01、AUD-R2-02、AUD-R2-03 与文档收尾顺序作补充；不扩展 Advanced 功能。§12.1–§12.3 与前文具有同等约束力，并将旧文存在的不明确措辞精确化。后续审计核销前，本 SPEC 不得标记 FROZEN。

### 12.1 AUD-R2-01 — Prompt CAS 权威基准与规范化（MINOR）

**唯一权威数据**是 `user_config.json` 中对应模式的持久化 Prompt 映射，Easy 对应 `text.prompts`，Advanced 对应 `text.advanced_prompts`。内置 Default 的 UI 展示、Advanced 动态 Default、旧镜像 `prompt.json`、搜索过滤结果、当前未保存草稿**均不参与 CAS 摘要**。不能对 `_load_prompts()` 返回的多源合并视图直接计算 CAS。

规范化函数 `normalize_prompts(raw, mode)` 的输入为已在配置迁移边界处理完毕的**权威配置映射**，输出为仅含合法 `str→str` Prompt 名称/内容的完整映射；名称、内容保留原始 Unicode 与大小写，不 trim、不做大小写折叠；非法数据报配置错误而非自动丢弃或转换；按键的 Unicode 码点序进行稳定排序，使用固定的 `ensure_ascii=False`、`sort_keys=True`、固定 JSON 分隔符编码 UTF-8，再以 SHA-256 计算摘要。CAS 计算方、比对方和提交后的更新方必须共用**同一个函数**。

- 模式的配置键**缺失**：在首次受控初始化/迁移中明确写入空映射 `{}` 后计算摘要；不得用 UI 里注入的 Default 代替。持久化的**空映射**摘要即空映射的规范化 JSON 摘要。
- **仅内置 Default**：Easy 如持久化存有名为 Default 的用户 Prompt 文本，它是真实权威映射的一部分，纳入 CAS；如果 Default 只由 UI/内置常量注入而不在磁盘上，**不纳入 CAS**。两种状态不得混淆，且不允许以视觉上相同为由跳过必要迁移。
- **Advanced 动态 Default**：始终不进入持久化 Prompt 映射，不能成为 CAS 的一个条目。
- 每次模式域 Save/Save As/Delete/Import 在同一配置互斥锁内完成：读取**最新磁盘配置** → 使用同一规范化规则计算**磁盘权威映射**摘要 → 与窗口持有的该模式基准摘要比较 → 通过后仅在最新配置上应用本次修改 → 原子落盘 → 使用已提交映射计算新的窗口基准摘要。冲突时拒绝操作、保留草稿、不覆盖数据。
- 迁移先在原子配置事务中完成旧 `prompt.json` 的一次性导入及迁移标志持久化，**再**提供给 UI CAS 初始基准。完成标志后，镜像不得参与正常加载或摘要，不得使已删除 Prompt 复活。迁移/删除、缺键初始化和失败回滚必须有独立测试。
- 如果其他窗口只修改 Audio、Provider 或另一模式 Prompt，当前模式摘要不变，允许在最新配置上写入当前模式；如果另一个窗口修改同一模式 Prompt 映射（即使改不同名称），摘要不同则明确拒绝，避免基于陈旧状态覆盖。

验收反例：计算 UI 合并后的 `{"Default":"built-in"}` 与磁盘 `{}` 的摘要进行比较并报冲突；将旧镜像删除后的残留条目参与摘要；用旧窗口整个 Text 配置覆盖另一窗口新模型参数。这些均不符合合同。

### 12.2 AUD-R2-02 — 最终冲突检查与提交的不可让出边界（MAJOR）

对每条笔记，**最终**重新读取当前 Note → 对照 §11.6 的 Note Type ID、完整字段名顺序、全部 S/D 原始存储值 → 检查取消标志与操作上下文仍有效 → 设置全部 D → 调用**一次**受 Anki 官方事务/Undo 支持的提交 API，必须属于**同一不可让出执行权的 collection 操作单元**。该单元中**不得**：

1. 执行 `await`、`sleep`、进入嵌套 Qt event loop 或 `processEvents()`；
2. 调度给其他 Qt/Anki task 后继续用旧检查结果写入；
3. 运行会重入 UI 的 modal 对话框、网络请求、模型推理、磁盘外部等待；
4. 在重新检查后再从 UI 获取可变的字段/Prompt 选择或复用缓存 note 对象。

全部 LLM 推理、JSON 解析、批次确认、Prompt/Provider 校验、输入快照建立都在这一单元**之前**完成，工作线程不能直接接触 Anki collection。不可让出单元只允许在 Anki 受支持的 collection 串行执行上下文运行；如官方 API 内部会异步调度，应在实际**提交执行的回调内部**进行最后读取与比较，而不是在调度前比较。实现者必须提供相应目标 Anki 版本的官方 API 调用顺序和实机验证证据，不得声称 Python 代码顺序执行天然保证没有其他写入竞争。

提交进入不可中断阶段后，取消只能影响**后续**笔记，不能中途撤销当前笔记的半次写入；如果取消发生在真正提交之前则该笔记零写入。提交成功仍须满足 §11.5 的 Undo 能力和 UI 成功判定，提交失败不得报告成功。不能找到满足该操作单元要求的 Anki API 或事务策略，则阻断 Advanced 发布，不得降级为“检查后异步等待再写”。

必须验收：检查后模拟其他编辑排队到真正提交之前；如最终检查在实际提交回调内，能够识别冲突并零写入；模拟 Cancel 与提交临界点竞态；禁止任何异步让出发生在最终检查与提交之间。

### 12.3 AUD-R2-03 — Cloze 递归解析与异常拒绝（MINOR）

在 HTML 转换后的可读文本上，按原始字段的 Cloze 标记（而不是 Advanced Prompt 占位符）进行**确定性递归解析**。有效 Cloze 记号文法是 `{{cN::答案}}` 或 `{{cN::答案::提示}}`，其中 N 为正整数且不得有前导 0；答案可以包含文本和进一步完整嵌套的 Cloze，提示为纯文本且不能再包含 Cloze 标记。解析时识别配对花括号和顶层 `::` 分隔符；将每个有效 Cloze 转为**递归展开后的答案文本**，丢弃 `cN::` 与提示文本。不同 N 不影响行为；即使模板一次显示单个 Cloze 编号，转换也保留所有答案内容。

- 有效：`{{c1::answer}}` → `answer`；`{{c2::outer {{c1::inner}} tail::hint}}` → `outer inner tail`；`{{c1::answer::hint}}` → `answer`。
- 不合法：`{{c0::x}}`、`{{c01::x}}`、缺少右括号、提示中嵌套 Cloze、空答案、无法唯一定位顶层分隔符或非配对的 Cloze 起始标记。这些都使该 Source **无效**，由 §11.2 整批拒绝，不能把残留 `cN::` 控制串送给模型。
- **普通字面双大括号**（例如 `{{literal}}`）不是 Cloze，不应由本 Cloze 处理器替换或直接报错；但疑似 Cloze 起始 `{{c` 后跟数字、冒号或控制串的文本若解析不完整，必须拒绝，不能按普通字面文本放行。任何部分解析失败时不得返回部分输出。
- 保留原普通正文及换行，Cloze 解析只改写识别出的完整 Cloze 片段；之后按 §11.8 完成 HTML/entity/空白归一化。HTML 中被媒体、script、style 丢弃的内容不得先送入 Cloze 解析器产生误判。

验收包含：单层、多个不同编号、两层及三层嵌套、外层提示、嵌套提示、异常闭合、空答案、字面双大括号、包含 Unicode/HTML entity 的答案，以及与 §11.1 Prompt 转义无关的情况；只读已有字段，不新增 OCR。
